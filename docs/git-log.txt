    fix(security): rate limiting per real client, password policy, config hardening (S1, S3, S4, S5, S7, S9)

- S1: TRUST_PROXY must be set explicitly in production (empty counts as unset).
  Behind the web proxy every client previously shared one rate-limit bucket, so
  one client could block all guest RSVPs and logins. Log a one-time
  trust_proxy_misconfigured warning. Public per-IP default 60 -> 120/min.
- S3: login limiter keyed per email + client IP, with a higher email-only
  ceiling, so a third party cannot lock a victim out.
- S4: per-user request ceiling on authenticated routes; throttle audit rows for
  denied access (probing random workspace ids flooded the audit log).
- S5: password policy (distinct characters, repetition, sequences, common words).
- S7: optional SUPPRESSION_HASH_SECRET, falling back to PSEUDONYM_SECRET.
- S9: DOCS_ENABLED; API docs are off by default in production.
- Refuse to reuse one secret for CSRF and pseudonymisation in production.
